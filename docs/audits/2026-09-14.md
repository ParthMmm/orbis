# Axiom audit report — 2026-09-14

Nine Axiom auditor procedures ran read-only against the Apple client (`apps/apple`) at
`a8af6cc`, the commit that added audio download and playback, plus a Human Interface Guidelines
pass over the decisions the audits raised. Findings below are static: no runtime, Instruments,
Thread Sanitizer, or VoiceOver verification. The Bun/Effect server and the Electron desktop are
outside the Axiom suite's scope and were not audited.

Scope: `Orbis/*.swift`, `OrbisDesign/Sources/**`, `OrbisTests/**`, `OrbisUITests/**`.
Excluded: `DerivedData/`, `OrbisDesign/.build/`.

## Method

The concurrency audit ran as a subagent following `concurrency-auditor.md`. The other eight ran
inline in this session following their own procedures, because a nine-lane subagent fan-out lost
eight lanes to a harness acceptance check and exhausted the session spawn budget. Every finding
was re-verified against the source, and every quote is from that source. The HIG pass followed
`axiom-design` (`skills/hig.md`) and `axiom-accessibility` (`skills/accessibility-diag.md`).

A second session worked in this repository at the same time, on an iPhone design review recorded
in `docs/audits/2026-09-14-iphone-design-review.md`. Its findings are its own and were not
touched here. One of its screenshots was used as evidence below.

## HIG pass

What the guidelines decided, beyond the table above:

- **Touch targets** — 44×44 pt on iOS and iPadOS, 20×20 pt on macOS. The design system already
  encoded this split in `orbisRowHeight()`; the Tag remove button was the one control that missed
  it. Verified as the only undersized target: the other small frames in the package are
  decorative dots and swatches inside larger rows.
- **Spacing** — `hig.md` says to omit lengths and let the system supply them, and to treat a
  literal as a justified exception. `OrbisMetrics` states the same rule ("Spacing has no scale"),
  yet components carry literals such as `padding(.horizontal, 7)`, `padding(.vertical, 4)`, and
  `HStack(spacing: 5)`. Left alone: changing them re-tunes every component's density and
  invalidates the accessibility matrices the package draws, which is a design decision rather than
  a repair. It is a real inconsistency between the stated rule and the code.
- **Typography, appearance, motion, RTL** — already compliant: every font is a Dynamic Type text
  style, colours resolve through four appearance values with an APCA gate, motion answers Reduce
  Motion, and `LayoutTests` reads the package sources to forbid physical offsets.
- **Reduce Transparency** — nothing to do: chrome uses system Liquid Glass (`.glassEffect`), which
  the system already degrades.
- **Colour-only meaning** — the two selection surfaces were the remaining case; both now carry a
  mark and a trait.

## Regression check against `docs/audits/2026-09-11.md`

Fixed since: keychain update-before-add, the `WhenUnlockedThisDeviceOnly` accessibility class, the
per-row `ISO8601DateFormatter`, eager list rows now `LazyVStack`, HTTPS required with a loopback
exception, the closed `SetSource` enum now carrying `.unknown(String)`, colour-only selection, the
missing privacy manifest, the debug log redaction, and the Tag removal target.

Persistent: the download watch still polls at a fixed second with no backoff, and no spacing scale
exists to replace the literals.

Corrected from the 2026-09-11 report: it listed missing `@ScaledMetric` and download state absent
from list rows. Rows do show download state (`SetPresentation.state(of:)` feeds `SetRow.State`), so
the real gap was the finished download never reaching the row, which is now fixed.

The baseline before any of this work was 115 unit tests, all passing, so no test was weakened to
make the work pass.

**The journey failure is not attributable to these changes.** With every change stashed, the same
test failed the same way at the same assertion, so it fails on a clean tree. The screen itself is
correct: the other session's screenshot of the Search destination shows its field. The test asks
for `app.searchFields`; the runtime at hand does not expose the control as that element type. A
later run also failed four other journeys at the connection step, while a second session was
driving a booted iPhone 17 Pro simulator with `agent-device` on this machine; those failures
disappeared on re-run. The journeys need a quiet machine to be evidence, and the Search assertion
needs to accept the element type the runtime actually publishes.

## Cross-cutting priorities

Findings from several audits converge on the same work. In priority order. Items 1 to 5 and the unknown-source part of item 6 landed on 2026-09-11 as `dd94417`, `9443e25`, `9d6d1b9`, `36720f9`, `47bc299`, and `18f38e3`, with the forget confirmation as `45bb6ae`:

1. **Playlists never load after pairing until relaunch.** `AppModel.connect()` loads only the library; the startup `.task` skips rerun once `library != .idle`; playlist failures land in `.loaded([])` and look empty. Fix: load playlists on connect, keep `.failed` states, offer retry. (UX)
2. **No request generations, so superseded work publishes stale state.** Library and search responses can arrive out of order; connection tests and metadata retries can commit after their screen closed; `forget()` leaves pending reads running. One fix covers it: generation/identity guards plus owned, cancellable tasks per operation. (Concurrency + UX)
3. **Writes give no progress and can violate the active playlist view.** `isWorkingOnSet` has no view consumer; filing and moving Sets do not reconcile the filtered list. Fix: surface progress, reconcile or reload after writes. (UX)
4. **Rendering-time work in hot paths.** `ISO8601DateFormatter` is allocated per parsed timestamp on every row render; Library/Search rows use eager `ScrollView` + `VStack` instead of `LazyVStack`; tag suggestions use eager `HStack`; library derivation re-runs per render. Fixes are small: cached formatters, lazy containers, cached derivation. (Performance)
5. **Credential handling.** Keychain delete-then-add can lose the token if the add fails — update first, then insert, and check status. The accessibility class should be `WhenUnlockedThisDeviceOnly` unless a background need is documented. Bearer requests accept non-HTTPS addresses — require HTTPS with an explicit DEBUG loopback exception. The DEBUG macOS `~/.orbis/config.json` token fallback stays development-only by design. (Security + Storage)
6. **Decoding robustness.** Five `try?` decodes discard `DecodingError` diagnostics; the closed `SetSource` enum fails the whole library decode if the server adds a source; per-call coders invite strategy drift. Fix: log decoding paths redacted, accept unknown sources, centralize coders. (Codable)
7. **Privacy manifest.** `UserDefaults` requires a declared reason (`CA92.1`) in `PrivacyInfo.xcprivacy` before any TestFlight or App Store submission. Nothing is being submitted yet, so this is a tracked blocker, not a today-fix. (Security)
8. **Accessibility Level A gaps.** Sidebar and destination selection are color-only (add `.isSelected` trait plus a visible checkmark); the combined detail header drops the visible subtitle; tag removal targets are under 44pt. Also: tag sheet overflow at AX5, fixed spacing without `@ScaledMetric`, missing keyboard shortcuts. (Accessibility)
9. **Debug logging redaction.** Three `#if DEBUG` stderr writes expose full URLs (including search terms) and response heads. Switch to `Logger` with `.private` fields or drop the content. (Security)

Memory needs no work: the static audit found zero issues.

## Issues by Severity

### [HIGH/HIGH] Task self capture: cancelled load starts an unowned retry

**File**: apps/apple/Orbis/AppModel.swift:222 **Phase**: 2: Detection (pattern 2) **Evidence**: `Task { await loadLibrary() }`, inside `catch OrbisError.cancelled`, guarded by `reloadsAfterCancellation < 2`. **Issue**: The class method implicitly captures AppModel strongly and discards the task handle. Cancelling the requesting view deliberately creates work outside its lifecycle. **Impact**: The retry retains the model during its request and can continue after the view disappears. This is bounded lifetime extension, NOT a stored-task retain cycle or proven permanent leak. **Fix**: The suite recommends `Task { [weak self] in await self?.loadLibrary() }`. This avoids retention before task execution, but still retains the model during the awaited method. For lifecycle control, own/cancel the retry handle or let an active view restart a lifecycle-managed `.task` instead of restarting cancelled work. **Cross-Auditor Notes**: Memory lifecycle overlap; no stored-task compound applies.

### [MEDIUM/HIGH] Request lifetime: superseded reads can publish stale results

**File**: apps/apple/Orbis/AppModel.swift:212, 456-478; apps/apple/Orbis/RootView.swift:119-121, 355-359 **Phase**: 3: Completeness **Evidence**: `library = .loaded(try await client.library(playlistId: selectedPlaylistId))`; `search = .loaded(try await client.library(query: query))`; `.onSubmit(of: .search) { Task { await model.runSearch() } }`. **Issue**: Independent tasks overlap across MainActor suspension points. No task handle or request identity prevents an older playlist/search request from publishing after a newer one. Clearing search sets `.idle` without invalidating its pending request. **Impact**: Older responses can overwrite newer results, show the wrong playlist, or restore cleared search results. Error/cancellation handlers can also overwrite newer state. This is a logical ordering race, not an actor data race. **Fix**: Apply the suite's lifecycle guidance: keep a cancellable read task per operation or use `.task(id:)`; cancel superseded work. Guard all success/error/cancellation publication with request identity, e.g. `guard generation == currentGeneration, !Task.isCancelled else { return }`. Invalidate identity when clearing search or changing playlist. Cancellation alone cannot reject an already-completed response.

### [MEDIUM/HIGH] Operation lifetime: dismiss/reset does not invalidate pending commits

**File**: apps/apple/Orbis/AppModel.swift:163-166, 192-205, 321, 334; apps/apple/Orbis/ConnectionView.swift:41, 58 **Phase**: 3: Completeness **Evidence**: `_ = try await candidate.health()` precedes `ClientSettings.serviceAddress = url.absoluteString` and `client = candidate`. `closeConnectionEditor()` only clears failure/editing state; `forget()` clears client/library/search without cancelling work. Metadata retry executes `reveal = Reveal(...)` after an await; `closeReveal()` sets `reveal = nil`. **Issue**: Operations can commit into a dismissed/reset UI or session. “Keep the library I have” remains available during connection testing. Closing a reveal does not invalidate metadata retry; forgetting a device does not invalidate pending reads. **Impact**: A dismissed connection test can replace persisted settings; late responses can repopulate reset data or reopen a dismissed reveal. **Fix**: Give operations owners and cancellation handles as the suite recommends. Cancel/invalidate work in close/reset methods and check session/editor/reveal identity before committing results or credentials: `guard sessionGeneration == currentSessionGeneration, !Task.isCancelled else { return }`. Discard obsolete UI updates; this need not undo committed server mutations.

## Recommendations

1. Own cancellation retry work and remove unconditional strong capture.
2. Add cancellation and generation guards to replaceable reads and dismissed/reset operations.
3. Confirm the intended app default isolation before migration: only OrbisDesign opts in. No substantial CPU-heavy async body was established; no speculative @concurrent/UI-freeze finding is reported.

**Overall posture: NEEDS WORK.** No proven Sendable, actor-access, or detached-task violation; compiler verification remains outstanding. Scan inventory and limitations follow.
